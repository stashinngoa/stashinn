# Stage 2 — Batch B: Customer Discovery Complete

The Demand Side of the StashInn platform is fully operational. Customers can now securely search, discover, inspect, and book physical luggage storage locations generated by the Supply Side (Batch A).

---

## 1. Geo-Search RPC Migration (CM-04)
I authored a custom PostGIS RPC function named `search_nearby_locations`. This engine natively filters for `is_active` locations owned by `approved` partners and calculates accurate geographic distances using `ST_Distance(geo_point, ST_MakePoint(lng, lat)::geography)`.

> [!WARNING]
> Because my remote access to your local docker container was actively refused, the Supabase CLI migration failed to execute automatically. **You must run `npx supabase migration up` in your terminal** or copy the SQL from `supabase/migrations/20250412000001_search_rpc.sql` and run it manually in Supabase Studio.

## 2. Customer Homepage & Search (CM-01)
The root of `apps/customer/app/page.tsx` has been transformed into a premium, glassmorphism-inspired **Search Engine**.
- Customers input their Drop-off time, Pick-up time, City, and Number of Bags.
- The UI handles formatting and pushes these constraints into the `/search` URL parameters.

## 3. Search Results Map UI (CM-02)
When the customer lands on `http://localhost:3000/search`:
- **Dynamic Leaflet Map:** A split-screen UI featuring an interactive OpenStreetMap component powered by `react-leaflet`. It automatically calculates the bounding box of the results and fits the map to show all relevant location pins.
- **Location Cards:** A scrollable list on the left displays the active partner locations matching the query.

## 4. Location Details & Sticky Booking (CM-03)
Clicking a location opens `http://localhost:3000/locations/[id]`.
- Displays the photo gallery (which you uploaded via the Partner Portal), amenities, and exact operating hours.
- **Sticky Booking Sidebar:** Dynamically captures the Drop-off/Pick-up times and calculates the total price by multiplying the requested duration by the partner's fixed `price_per_hour` (with built-in logic capping to the `price_per_day` rate!).

## 5. Booking Checkout Flow (CM-05)
Clicking "Book Now" transfers the user to `http://localhost:3000/checkout`.
- **Auth Guarding:** The checkout page enforces authentication. If the customer isn't logged in, they are rerouted to `/login` with a persistent callback URL so they don't lose their booking configuration!
- **Server-Side Creation:** Upon clicking "Confirm & Pay at Location", a Server Action safely injects the data into the `public.bookings` database table with `status = 'pending'`, and redirects to a Success confirmation screen.

### Verification Checklist
Test the end-to-end customer journey on `localhost:3000`:
1. Run `npx supabase migration up` (if you haven't already).
2. Go to `http://localhost:3000/` and search for "Goa" (or wherever you placed your dummy location).
3. Confirm the Map correctly displays the pin and the list shows your Location Card.
4. Click through to the Location Details page, confirm the calculated price in the sidebar.
5. Click **Book Now**.
6. If prompted, Login/Register a Customer account.
7. Confirm the Booking, and verify it exists in your Supabase `bookings` table!
